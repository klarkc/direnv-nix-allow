# AGENTS.md — direnv-nix-allow

## Project Summary

Small Haskell CLI that lets direnv reuse an existing approval when two `.envrc` files are equivalent, boring, and Nix-backed. See [`docs/wip.md`](docs/wip.md) for detailed handoff context.

## Validation Contract

After each change run:

```sh
nix fmt
nix flake check
```

`nix flake check` is the source of truth. All checks must pass (exit 0). Expected non-fatal warnings: app lacks `meta`, `system` rename warning, transient SQLite busy messages, and local `aarch64-linux` omission (covered by CI).

## Trust & Security Rules

- No separate trust database; use direnv's allow directory as source of truth.
- Only reuse approval for a strict subset of boring `.envrc` files.
- Reject arbitrary shell snippets and `use flake --impure`.
- Identity must include: normalized `.envrc`, flake content hash, installable, system, and impurity flag.

## Interface Preference

Prefer external interfaces in this order when available, stable, and cheap enough:

1. CLI interface
2. Code/API interface
3. Direct file interface

This is a preference, not an absolute rule. Use direct file access when the file is the documented source of truth or there is no adequate CLI/API.

Current justified file-interface exception: reading direnv allow files to enumerate already allowed `.envrc` paths, because no known stable `direnv` CLI exposes that exact list.

## Known Warnings (Non-Fatal Unless Behavior Changes)

- `app 'apps.x86_64-linux.default' lacks attribute 'meta'`
- `'system' has been renamed to/replaced by 'stdenv.hostPlatform.system'`
- Transient SQLite database busy messages from the Nix store
- Local `aarch64-linux` skip (covered by CI matrix)

## Pre-commit Hook Caveat

Stale pre-commit hooks may complain about missing `.pre-commit-config.yaml` (generated by `nix develop`, intentionally ignored). Workaround:

```sh
PRE_COMMIT_ALLOW_NO_CONFIG=1 git commit ...
```

Do not commit `.pre-commit-config.yaml` unless project policy changes.

## Next Implementation Target

Replace `system=default` in the identity with the real Nix system:

- Add a helper that runs `nix config show system`, trims output, rejects empty values, and fails closed on failure.
- Call the helper from `computeIdentity` in `src/DirenvNixAllow.hs` and emit `system=<value>` instead of `system=default`.
- Do not use `nix eval --impure --expr builtins.currentSystem`.
- Factor identity rendering into a pure helper so tests do not need to invoke `nix`.
- Validate with `nix fmt` and `nix flake check`.
